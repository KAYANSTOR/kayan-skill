# FreeLLMAPI

## الاستخدام
FreeLLMAPI موجّه محلي يجمع مزودي النماذج المجانية خلف endpoint متوافق مع OpenAI، ويدعم routing وfallback وقياس الاستخدام. اقرأ `README.md` والمستندات الأصلية قبل تثبيت إصدار أو اختيار مزود؛ الأعداد والحصص تتغير.

المصدر: https://github.com/tashfeenahmed/freellmapi
الموقع: https://freellmapi.co/

## سير العمل الآمن

1. افحص النظام وإصدار Docker أو Node قبل التثبيت.
2. اقرأ تعليمات الإصدار الحالي بدل افتراض أن أمرًا قديمًا ما زال صحيحًا.
3. فضّل clone أو release موثقًا ومراجعة script قبل تشغيله. لا تمرر `curl | bash` تلقائيًا؛ اعرض المصدر واطلب موافقة إذا كان التثبيت مطلوبًا.
4. شغّل الخدمة محليًا أو داخل بيئة معزولة، ثم افتح لوحة التحكم محليًا فقط.
5. أضف مفاتيح مزودي الاختبار من مدير أسرار أو متغيرات بيئة. لا تحفظها في Git أو تقارير الوكيل.
6. اختبر health endpoint وmodel listing وfallback على بيانات غير حساسة.
7. اربط الوكيل بعنوان محلي OpenAI-compatible. استخدم `npx freellmapi setup-claude` فقط بعد مراجعة ما سيعدله ونسخ الإعداد السابق.
8. لا ترسل كودًا خاصًا أو أسرارًا إلى مزود مجاني إلا بعد مراجعة سياسة الخصوصية والمخاطر. استخدم نموذجًا محليًا أو بيانات منزوعة الحساسية عند الحاجة.
9. سجّل الإصدار، المزودين، endpoint، والخطة، لكن لا تسجل المفاتيح أو prompts الحساسة.

## القيود

النماذج المجانية لها حدود يومية وتفاوت في الجودة والسرعة والتوافر. مجموع التوكنات لا يعني أن نموذجًا واحدًا يملك هذه السعة. اعتبر الخدمة مناسبة للتجربة والتطوير والمهام غير الحساسة، ولا تفترض SLA أو خصوصية إنتاجية دون تحقق.

## التحقق

- [ ] الخدمة تعمل محليًا ولا تستمع علنًا بلا حاجة.
- [ ] مفاتيح المزودين محفوظة خارج Git.
- [ ] endpoint وmodel fallback اختُبرا.
- [ ] إعداد الوكيل الحالي محفوظ قبل الدمج.
- [ ] لا توجد بيانات سرية في logs أو prompts أو traces.
- [ ] خطة الإيقاف والحذف معروفة.
